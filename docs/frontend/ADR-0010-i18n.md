# ADR-0010 — i18n: i18next, English first, Hindi later

**Status:** Accepted 2026-10-13 (locked by the user, §11)
**Plan ref:** Front-End Rebuild Plan §2

## Decision

- i18next with `src/i18n/en.json` as the single string catalogue;
  components never embed user-facing strings from F3 (first shell
  components) onward.
- **English first.** `hi.json` is added in a later pass — wiring exists
  from day one so Hindi costs translations only, no code changes.
- Counts, dates and numbers go through i18n formatters (UTC in, local out).

## Consequences

- A CI check can assert that feature files contain no raw user-facing
  literals once F3 lands (adopted with the shell, not before).
