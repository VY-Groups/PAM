# ADR-0014: Architecture Explorer (interactive HTML, generated)

Date: 2026-10-17
Status: Accepted
Supersedes: nothing (extends the ADR-0013 artifact set)

## Context

The five Mermaid docs under `docs/architecture/` (ADR-0013) are readable
but static. A hand-authored prototype — `VY-PAM Architecture Explorer2.html`,
written outside the generator — demonstrated a better interaction model:
four views (System map, Console ↔ API, Backend modules, Workflows),
search, per-node detail panels, and derived observations. Its numbers
were correct at the time it was written, but every figure was a
hand-embedded literal (`TG`, `R`, `PK`, `WF` strings inside the page).
Nothing stopped them from going stale the moment the extractor output
moved — screen 11 (Settings) alone will change route and tag wiring.

Rule this repo does not break: **a committed artifact that states facts
must be generated from the sources those facts come from, or it is vibe
coding.**

## Decision

1. `docs/architecture/architecture-explorer.html` is **generated by
   `pnpm topology`** (frontend/app/scripts/topology.mjs) from the same
   six sources as every other artifact of the set, and is covered by the
   **existing** CI drift gate: the topology step's
   `git diff --exit-code -- src/features/topology/topology.generated.ts ':(top)docs/architecture'`
   already scopes the whole directory. No workflow change is required.
2. The page **chrome** (CSS, interaction JS, panel copy, the editorial
   domain grouping) is hand-edited in
   `frontend/app/scripts/architecture-explorer.template.html` — a
   prettier-checked file with a single `__DATA__` placeholder. The
   generator injects one deterministic JSON blob (`const DATA = …`).
   Everything the page states as a number or relationship comes out of
   that blob; observations in the panel are computed at runtime from it,
   never stored as prose.
3. The generator throws loudly on any pattern it cannot build: an
   editorial domain that references a tag the contract does not have, a
   package name the layout does not cover, a module order the grid was
   not sized for. A missing pattern fails the build; it never renders a
   guess.

## Wired-state rule (policy, not parsing)

Per API tag, derived from live routes' resolved contract operations
(the exact edges `frontend-map.md` draws) and the Network posture's
passive reads (`queries.ts` hooks: `GET /health`,
`GET /api/v1/cluster`, `GET /api/v1/integrations/status`):

| State | Meaning | Rule |
|---|---|---|
| `0` | not in the route map | no live route resolves any operation of the tag |
| `1` | partly wired (overview only) | the tag is touched, but only by the network posture's passive reads |
| `2` | wired to a console route | at least one live route drives an operation outside the passive set |

Pending routes (`legacyHref` set, ADR-0012) never contribute: the legacy
page does not use the generated client, so their endpoint list is empty
by construction. Shell-level calls (guard/session hooks outside any
feature) are out of scope for every artifact in this set — the explorer
says "the calls a route's screen makes", exactly like frontend-map.

## Verification layers

1. **CI regenerate-and-diff** — `pnpm topology` then
   `git diff --exit-code` over `':(top)docs/architecture'` (covers this
   file with no ci.yml change).
2. **vitest re-parse** (`topology.generated.test.ts`, ADR-0014 block) —
   extracts the `DATA` blob from the committed HTML and re-derives every
   claim independently: tag names/counts against the re-parsed
   openapi.yaml, route rows and per-route tags against
   `FRONTEND_ROUTES.endpoints`, wired states against the rule above,
   package grids against `BACKEND_PACKAGES`, workflow steps against the
   contract, domain groupings against the emitted tags.
3. **Rendered-output check** — the page must load with zero console
   errors and all four views built (headless Edge spot-check before any
   commit touching the generator or template).

## Consequences

- The prototype's hand-embedded data goes away; the committed page is a
  pure function of the six sources. Regenerating is one command.
- `VY-PAM Architecture Explorer2.html` (the prototype) is superseded and
  must not be committed — it is untracked by design.
- The footer states the honest scope: snapshot of the generated files,
  not live node data; live values belong to `/topology` in the console.
- Editorial content that is not extracted (domain grouping, panel
  wording) stays in the template and is labelled editorial on the page.
