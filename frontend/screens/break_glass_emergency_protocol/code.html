Acting identity

Recorded verbatim as X-Actor on every action. The server enforces dual approval: the requester cannot approve their own emergency, and the second signature must come from a different identity.

Dual approval process
  1. 1. Request filed — reason, severity and target recorded verbatim; status pending.
  2. 2. First signature — an approver who is not the requester signs (1/2). Nothing is released yet.
  3. 3. Second signature — a different approver signs (2/2) → status approved.
  4. 4. Unseal — the credential is checked out of the vault and a session starts with recording forced.
  5. 5. Close — session ends, the credential ends up rotated, and the post-incident review note is required.
MFA: not configured (no factor enrolled — no challenge is simulated).
Safeguards
  • videocamRecording forced — record=true is set server-side regardless of operator preferences.
  • vaultReal vault checkout — the emergency credential is checked out through the vault inventory; the target must carry one.
  • syncRotation guaranteed — the released credential ends this flow rotated exactly once (session-end cascade; close forces whatever is still owed).
  • gavelAudited end to end — requested / approved / denied / opened / closed all land on the hash-chained break-glass trail.
  • task_altReview required — an emergency without a post-incident review note cannot be closed.
